# AGENTS.md

FactoriOS runs Factorio's macOS binary on iOS. It converts the binary into a signed dylib on the Mac, embeds it in an
xtool-generated app, and loads it next to SDL3 for iOS and an Objective-C compatibility layer. Read
[docs/architecture.md](docs/architecture.md) before changing code.

## Map

| Path | What |
|---|---|
| `Sources/FactoriOSCore` | Platform-independent Swift: Mach-O converter, settings, controller logic |
| `Sources/FactoriOSRuntime` | iOS: install check, `dlopen`, compat slot patching, game session, SDL input |
| `Sources/FactoriOSCompat` | Objective-C: Mac API replacements, Metal fixes, BC decode, SDL bridge |
| `Sources/FactoriOSUI` | SwiftUI launcher and UIKit controller overlay |
| `Sources/FactoriOSApp` | `@main`; hands start-up to `SDL_RunApp` |
| `Sources/FactoriOSConvert` | Mac CLI `factorios-convert`: the Mach-O conversion `scripts/device` runs |
| `scripts/` | `setup`, `device` (imports the `.dmg`, converts, signs, installs), `simulator`, `prepare-sdl3.sh`, `check-architecture` |
| `mise.toml` | Toolchain and every task (`mise tasks`) |

## Commands

```sh
mise run check       # lint, format, compat map, repo lint, core build (any host)
mise run check-ios   # clang-tidy and iOS device + simulator compile (macOS with Xcode)
mise run format      # apply swift-format
mise run device      # build, prepare, install, launch on the configured device (needs mise run setup)
mise run simulator   # launcher only; the game can't run in the simulator
```

Run `check` and `check-ios` after every change. `device` needs a connected device and a person to tap **Main menu**,
because the game doesn't start on its own.

## Rules

- The repository never contains Factorio files, converted libraries, or personal values (UDIDs, team IDs, paths).
  Per-machine values live in the ignored `mise.local.toml`. Build output goes to the ignored `artifact/`, `Vendor/`,
  `xtool/` and `.build/`.
- Warnings are errors: Swift 6 strict settings, Objective-C `-Weverything -Werror`, strict SwiftLint and
  swift-format. Don't suppress them; fix the cause.
- Keep logic in `FactoriOSCore` when it can be platform-independent. Its build is gated by `FACTORIOS_CORE_ONLY=1`.
- A new Mac API replacement updates `Sources/FactoriOSCompat`, `GameLibrary.redirectedSymbols` when it fills a slot,
  and the compatibility map in `docs/architecture.md`. `mise run check` verifies the map.
- `xtool/` is generated by `mise run xcode-project`. Edit `Package.swift`, `xtool.yml` or `Resources/` instead.
- The bundle ID comes from `FACTORIOS_BUNDLE_ID` through `PRODUCT_BUNDLE_IDENTIFIER`. Don't hardcode it.
- Docs are short and chart-first. Update the page that owns the topic (see the README's documentation table) instead of
  adding a new one.
